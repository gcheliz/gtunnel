Private GCP,
one localhost away.

A TUI-first manager for Identity-Aware Proxy tunnels. Reach a VM inside your VPC, or put a public HTTPS URL in front of your laptop. No open ports, no stored credentials, one binary.

$ cargo install --git https://github.com/gcheliz/gtunnel

Needs the Google Cloud SDK on your PATH. Then gtunnel init and gtunnel doctor.

The real TUI, recorded from gtunnel demo. It shows whether a tunnel is carrying traffic, not just whether a process is alive.

01

Nothing exposed

No inbound firewall rule, no public IP on the target, no agent on the VM. IAP authorises every connection against your own Google identity.

02

Nothing stored

gtunnel keeps no credential. Every token comes from gcloud at connect time, and access mode creates nothing in GCP.

03

Survives the terminal

Tunnels run as launchd or systemd --user services: restart on failure, optional start at login, one log each.

TWO MODES, ONE BINARY

In to your VPC. Out to the internet.

Access

A private port on localhost reaches a VM port through IAP. Add --via to jump to a host only that VM can see, like a private GKE control plane.

localhost:15432 ——▶ IAP ——▶ my-vm:5432 
$ gtunnel add db my-vm:5432 -s
$ psql -h localhost -p 15432

Public

A public HTTPS URL on your own domain in front of a service on your laptop, through a relay VM and a global HTTPS load balancer.

api.example.com ——▶ relay ——▶ localhost:3000 
$ gtunnel relay up
$ gtunnel expose web 3000
ON THE FLY

Need it for five minutes?
Just run it.

gtunnel run opens a tunnel in the foreground and closes it with Ctrl+C. Nothing to declare first, nothing left behind after.

# prints the local port
$ gtunnel run my-vm:5432

# the same, under a name
$ gtunnel run db my-vm:5432

# https://gt-<random>.<domain>
$ gtunnel run --public 3000

One command, no setup

Give it a target. The name is optional and a free local port is picked for you.

Leaves nothing behind

No entry in your tunnel list, no service installed. Every route it opened is torn down on exit, Ctrl+C and crashes included.

Still visible

While it runs, list, the TUI and doctor see it like any other tunnel.

Share a URL in seconds

--public puts a throwaway HTTPS address in front of localhost for a demo or a webhook.

FOLLOW THE PACKET

Where a connection goes, hop by hop.

Full screen

Access: laptop → VM

  1. psql, kubectl or Compass connects to a local port. As far as the client knows, the database is on your laptop.

    psql -h localhost -p 15432

  2. A launchd or systemd --user service runs gcloud for this tunnel, restarts it on failure, and writes one log for it.

    com.gtunnel.dev.db

  3. Identity-Aware Proxy authorises the connection against your Google identity. The token comes from gcloud at connect time; gtunnel stores none.

    35.235.240.0/20

  4. The only rule the VPC needs lets the IAP range reach the target port. Access mode creates nothing in GCP.

    my-vm:5432

Public: internet → laptop

  1. Anyone on the internet requests a hostname on your own domain, served over HTTPS.

    https://web.example.com

  2. gtunnel writes an A record, TTL 60, to the global address of the account’s load balancer.

    web.example.com. A gt-prod-ip

  3. It terminates TLS with a managed certificate, matches the host rule, and with expose --private asks for IAP sign-in first.

    host rule → gt-prod-web

  4. A named port selects this tunnel’s relay port. The relay has no public IP either: only the balancer reaches it.

    named port gt-web → 30001

  5. Your laptop holds a reverse SSH tunnel out to the relay, so the request arrives at the service on your machine.

    localhost:3000
